# Human verification of supply_values.csv: checklist

Prepared by Claude (AI) at BB's request, 2026-11-10. Follows [workflow.md](workflow.md) section 7 and the shared logging rules in [../literature_reforming/workflow.md](../literature_reforming/workflow.md) section 3b.

Work from [human_check_worksheet.csv](human_check_worksheet.csv). It has one row per value (195), grouped by source so each document is opened once. Sources are ordered by the most important use of any of their values:

| Priority | Values | Meaning |
|---|---|---|
| 1 | 35 | cited in an efficiency range of [supply_classes.csv](supply_classes.csv); these feed the wall-basis EC_CH4 |
| 2 | 34 | cited in a cost or lifetime entry of supply_classes.csv |
| 3 | 126 | other values (context, unit power, frequency, qualitative statements) |

The first 27 sources in the worksheet (PW003 to PW054) contain at least one priority 1 value; checking down to PW054 covers every efficiency range, and the next 12 down to RV005 (PW001 next) every cost and lifetime entry as well. The worksheet is generated by `python3 scripts/make_check_worksheet.py`; regenerate it if supply_values.csv changes before the check is finished (the `checked` marks are not carried over).

## Before you start

- [ ] Note the start time (minutes go into summary.csv).
- [ ] Have [../human_checks/findings.csv](../human_checks/findings.csv) and [../human_checks/summary.csv](../human_checks/summary.csv) open. Next check ID: one after the last HC number in findings.csv.
- [ ] Open the local copy given in the `local_copy` column (paths relative to power_systems/). Web pages are saved HTML; open in a browser and use find (Ctrl+F) on the quote.

## For each value (one worksheet row)

Tick `checked` with your initials when all apply. For each problem, add a row to findings.csv with `record_id` = value_id and the error code shown, and put the HC number in `finding_ids`.

1. **Locator** - the page, table or section in `location` leads to the quote. (L)
2. **Quote** - the quote appears verbatim in the copy. If it is not there at all, code H. Trivial differences (spacing, a dropped symbol) are severity 1.
3. **Value** - `value_as_extracted` matches the quote: number, unit, and W vs kW (some per-W prices are stored per kW, noted in `notes`). (V)
4. **Qualifier** - "up to", "approaching", ">", "~", "expected" are kept, not turned into a plain number. (I)
5. **Boundary** - `basis` is what the source measures: tube or transistor (`device`), amplifier or head only, whole generator from mains, into a load, supply stage only. For costs, `cost_scope` matches what the price covers (tube only, supply, turnkey system, supply + reactor) and the currency and year are right. (B)
6. **Class** - `supply_class` fits the item and the stated frequency. For cost rows, the unit size in `unit_size_kw` (supply_values.csv) is the size the price refers to, per `unit_size_ref`. (S, B)
7. **Data type** - vendor spec (named model, datasheet) vs vendor claim (marketing, family) vs measured vs estimate vs secondary is right. (Q)
8. **Omission** - nothing next to the quote changes its meaning (a condition, a footnote, a different operating point that should have been taken instead). (O)

Extra steps for flagged rows (`flags` column):

- **recompute from notes** (reviewer calculations, 9 rows): redo the arithmetic in `notes` from the input value IDs. (C)
- **read from page image** (scanned patents PW040, PW047; PW026 Table IV): the AI read these from rendered images, not a text layer; check digits carefully. (V)
- **source quotes another source** (secondary): check only that this source says it; the original is not checked here. Note in findings if the citation looks wrong. (I)
- **qualitative (no value)**: check the statement is quoted fairly. (I)
- **English and Spanish copies held** (PW019): the quote should be in the English version; check the Spanish if they differ.
- **SKIP: no local copy** (PW010-V01, -V02): cannot be checked; leave unticked.

Severity: 1 cosmetic (no value changes); 2 minor (a value changes, no class range or conclusion changes); 3 major (a class range, a wall-basis result or a statement in the notes changes).

## After each source

- [ ] Add one row to summary.csv: `source_id`, date, checker BB, `scope`, `records_checked`, `records_total` (rows for that source in the worksheet), findings, major findings, minutes, `status_after`.
  - scope `core` = all priority 1 and 2 values of the source; `full` = every value of the source. For this folder `core` is the minimum for human_verified.
  - `status_after`: `human_verified` if no findings, otherwise `pending_corrections`.
- [ ] A source with no findings still gets a summary row.

## Class table check (once, after the priority 1 and 2 sources)

For each row of [supply_classes.csv](supply_classes.csv):

- [ ] `eta_low` and `eta_high` follow from the cited `eta_value_ids` and the reasoning in `range_basis`; reviewer judgements (e.g. the J1 lower bound for transformer losses) are labelled as such. Log as record_id `<class_id>:eta` (I or C).
- [ ] The `cost` and `lifetime` text matches the cited value IDs. Record_id `<class_id>:cost` or `<class_id>:lifetime`.
- [ ] Spot-check the wall-basis table in [notes/scaleup_assessment.md](notes/scaleup_assessment.md) against `figures/scaleup_wall_basis.csv`.
